# M4 — Deployment on the platform

> Ref: `docs/architecture-proposal.md` §3.13–3.14 and the platform guide (`docs/platform.md`, version **2026-10-23**, verbatim copy). Exit demo: alice signs in at `https://sinapps.demo.bredda.eu` (valid certificate), runs a multi-tool turn with web search, and a rollout or a pod restart loses nothing but the in-flight answer.

## 0. Update 2026-10-23 (guide revised)

Decided by the owner, and applied below:

- **Images on `ghcr.io` are public.** No pull Secret. The owner makes the *package* public after the first push (a new package is private by default, whatever the repo's visibility), and checks it with an anonymous `docker pull` before the first rollout. (Q1 closed)
- **TLS to Postgres: encrypted, not verified, no CA distributed.** The Secret carries `sslmode=require` with the libpq meaning; node-postgres reads it as `verify-full`, so **the app must rewrite it to `sslmode=no-verify`** (verified on our `pg-connection-string` 2.14.1: gives `rejectUnauthorized: false`). It is now a small code task, no longer a blocker. (P2, Q2 closed)
- **Traefik's 180 s idle timeout is confirmed and will not change**: the SSE heartbeat is a requirement, not an option (P10).
- **`auth.bredda.eu` is reachable from a pod with a valid certificate** (verified 2026-10-23); an application fetching a real realm's discovery document is still untested (P5 narrowed).
- The repository is public: Flux reads it over HTTPS, **no deploy key**.
- Still **not decided** by the platform: where the app's Secrets live (SOPS, created by the owner), metrics and log conventions, HTTP→HTTPS redirect. Postgres: no extension needed by us.

## 1. Proposal: split M4 in two

- **M4a — deploy what exists** (this plan): the `web` component only. The platform path (Flux pulling the chart, cert-manager annotation, in-cluster access to `auth.bredda.eu`) has never been run and `sinapps` is its first test; finding its problems now, with a small app, is cheaper than after M1–M3.
- **M4b — keep up**: each new component (`mcp-genui` in M1, `sandbox` in M2) adds an image, a Deployment and a Service to the same chart, through the same release flow.

M4a needs no new feature. It needs a production runtime that does not exist yet (P1), and several decisions from the platform owner (section 4).

## 3. Findings

Checked against the code unless stated otherwise.

| # | Finding | Severity | What to do |
|---|---|---|---|
| **P1** | **No production server.** `vite build` outputs `dist/client` and `dist/server/server.js`, a fetch handler: nothing serves it, serves the static assets, handles SIGTERM or preloads `instrumentation.ts`. | Blocker | Choose a Node runtime (WP1): Nitro (documented TanStack Start path, emits a Node server) or a minimal custom server (`srvx`) around `server.js`. Decide with a one-hour spike, on image size, SIGTERM handling and SSE behaviour. |
| **P2** | **`sslmode=require` breaks with `pg`** (verified on `pg-connection-string` 2.14.1: parsed as `ssl: {}`, i.e. full verification, while the CNPG certificate is signed by a CA nobody distributes). **Decided 2026-10-23:** encrypted, not verified. | Medium (decided) | One helper in `packages/db`, `normalizeDatabaseUrl()`: `sslmode=require` becomes `sslmode=no-verify`, anything else is left alone (local URLs have no `sslmode`). Used by `createDb` and by the migration script, with unit tests. Never disable verification elsewhere. Re-check when `pg` 9 changes the meaning of `require` (the notice says it will adopt libpq semantics). |
| **P3** | **No health endpoints, no graceful shutdown.** An agent run lasts up to 5 minutes and holds the conversation's lock; a SIGTERM today kills the stream and leaves a `streaming` row for up to 5 minutes (the stale-lock release). | High | `/healthz` (liveness: process up, no dependency) and `/readyz` (readiness: `select 1` with a short timeout, config loaded). On SIGTERM: stop accepting, abort in-flight runs so they persist as `interrupted`, flush telemetry, exit; `terminationGracePeriodSeconds: 60`. |
| **P4** | **Proxy headers and HTTPS.** TLS ends at Traefik; there is **no HTTP→HTTPS redirect**. `BETTER_AUTH_URL` fixes the public origin (so the OIDC redirect URI and `Secure` cookies are right), but the app does not look at `X-Forwarded-*` anywhere else. | High | Set `BETTER_AUTH_URL=https://sinapps.demo.bredda.eu`; make sure the chosen runtime builds `request.url` from the forwarded headers; redirect `http`→`https` from `X-Forwarded-Proto` in the server entry unless the platform adds it (Q5). |
| **P5** | **Network dependencies.** `auth.bredda.eu` from a pod with a valid certificate: **verified 2026-10-23**. Still unverified: an application fetching a real realm's discovery document and keys, and the egress to `openrouter.ai` and `mcp.tavily.com` (the guide says nothing about egress filtering). The app boots without them, but sign-in or answers fail. | Medium | Q3: the owner runs the three checks from a pod before the first deploy; the commands go in `deploy/PLATFORM.md`. |
| **P6** | **Migrations.** `drizzle-kit` is a dev dependency; the e2e setup already uses `drizzle-orm`'s migrator, which is enough. A `pre-install,pre-upgrade` hook Job runs **before** the chart's own ConfigMaps and ServiceAccount exist, so it can only use the platform-provided `sinapps-database` Secret. | High | A small `migrate.ts` (migrator only) shipped in the same image; the Job needs nothing but `DATABASE_URL`. Drizzle's migrator is idempotent. |
| **P7** | **Realm file.** Our app reads realm roles from a top-level **`roles` claim in the id token** (custom mapper in the dev realm; Keycloak's default `realm_access` is in the access token only), and logs out through RP-initiated logout (needs `post.logout.redirect.uris`). The guide's skeleton has neither; it also wants `bruteForceProtected: true`, client id = app name (`sinapps`, ours is `sinapps-web`) and Keycloak 26.8.0 (dev compose pins 26.8.1). | Medium | `deploy/keycloak/sinapps-realm.json` = dev realm minus users and secrets, plus the mapper, the logout URI variable, brute-force on; rename the dev client to `sinapps`; pin dev Keycloak to 26.8.0. Variables: `SINAPPS_CLIENT_SECRET`, `SINAPPS_REDIRECT_URI`, `SINAPPS_POST_LOGOUT_URI`. |
| **P8** | **Roles are a snapshot.** They are decoded from the id token stored at sign-in; revoking the role takes effect only at the next sign-in, and better-auth sessions last 7 days by default. The id token itself *is* verified (signature against the discovery JWKS, nonce) by better-auth. | Medium | Decision for us, not the owner: shorten the session (proposal: 24 h absolute) or re-check roles with the refresh token. I recommend the short session. |
| **P9** | **Spend exposure.** The app is public on the internet behind Keycloak accounts created by the owner; cost tracking is read-only by design (no quota). One leaked or misused session can burn the OpenRouter key. | Medium | A dedicated production OpenRouter key with a **credit limit** set at the provider. Optional later: per-user run rate limit. |
| **P10** | **Long SSE streams through Traefik.** The 180 s idle timeout is confirmed and will not change: a silent model or tool call (a slow reasoning model, a long crawl) can cut the answer without a byte on the wire. Rollouts also cut in-flight streams. | High | SSE comment heartbeat every 15 s in `/api/agent` (required, covered by a test with a slow mock answer); check on the first deploy with a long answer. |
| **P11** | **Build is not hermetic.** `project.inlang/settings.json` loads its message plugin from jsDelivr at compile time (backlog item); a Docker or CI build fails when the CDN is slow. | Medium | Vendor the plugin (backlog item becomes M4a work). |
| **P12** | **CI never ran on GitHub** (T4, plus the e2e job added in T14). | Medium | WP0: push, fix, get it green before building anything on top. |
| **P13** | **Config file as values.** `sinapps.config.yaml` (models, MCP servers) must become a ConfigMap rendered from values, mounted at `SINAPPS_CONFIG`; MCP header secrets stay `${TAVILY_API_KEY}` references resolved from env, so they never enter the ConfigMap. | Low | Straightforward in the chart; add a values schema so a bad config fails at `helm lint`, not at pod start. |
| **P14** | **Production guards already in place**: env schema refuses dev defaults and requires `OPENROUTER_API_KEY` and `BETTER_AUTH_SECRET`; `/dev/parts` is not found outside dev; the mock model needs a flag that is ignored in production. | OK | Test them against the built image (WP2). |

## 6. Risks that stay open until WP8

- The Flux path for an app chart and the cert-manager annotation on an `Ingress` are "Designed, never run" in the guide (the hairpin to `auth.bredda.eu` is now verified for TLS, not yet for a real realm). Expect one or two iterations; each costs a release PR.
- Postgres connection budget: 100 connections shared with Keycloak and other apps; the pool stays at 10 and the app opens one pool per process.
- A node reboot is downtime, and rollouts cut in-flight answers (the interrupted marker is the intended behaviour, not a bug).
- The platform is shared and single-node: the production OpenRouter key and the Keycloak accounts are the only access controls, so P9 matters more than the usual "demo" laissez-faire.
